# FinanzIQ — Project Guide for Claude

## What this is
Personal finance dashboard for German payslips (DATEV format), bank statements (Kontoauszug), and store receipts (Kassenbons).
Two pipelines feed one single-page HTML dashboard served via HTTP.

## Workflow

```
downloads/
  payslips/         ← drop payslip PDFs (DATEV format)
  bank_statements/  ← drop bank statement PDFs (Kontoauszug)
  kassenbons/       ← drop receipt photos (JPG/PNG) + digital receipt PDFs
       ↓ (payslips + bank_statements)
scripts/process_payslip.py   → data/processed/data.json + manifest.json
       ↓ (kassenbons)
scripts/process_receipts.py  → data/processed/receipts.db + receipts.json
       ↓
build.py                     → dashboard/standalone.html  (data inlined, works via file://)
       ↓
launch.py / run.bat          → live dashboard via HTTP server
```

**Never open `dashboard/index.html` directly as a file.** `fetch()` is blocked on `file://` due to CORS. Use the HTTP server (`python launch.py`) or open `dashboard/standalone.html` instead (data is inlined, no server needed).

## Data structure

`data.json` has two top-level arrays:

```json
{
  "payslips": [ { "period": "2024-01", "gross": 5000, "net": 3200, ... } ],
  "bank_statements": [
    {
      "period": "2024-01",
      "balance": 22000.00,
      "transactions": [
        { "date": "2024-01-03", "merchant": "REWE", "amount": -45.20, "category": "Groceries" }
      ]
    }
  ]
}
```

**Transactions are nested inside each bank_statement entry** — not a flat top-level array.

`receipts.db` has two tables:
- `receipts` — one row per receipt: store, store_chain, date, total, subtotal, VAT, payment_method, item_count, validation_ok, validation_note
- `items` — one row per line item: receipt_id, raw_name, clean_name, category, qty, unit_price, total, vat_rate

`receipts.json` mirrors the DB as JSON for the dashboard — array of receipt objects with nested `items`. Auto-written by `process_receipts.py` on every run.

## Receipt processing (Kassenbons)

Drop receipt photos (JPG/PNG) or digital PDFs (Rossmann, DM, Penny, etc.) into `downloads/kassenbons/` and run:
```
python scripts/process_receipts.py
```
or double-click `run.bat` (runs all pipelines).

**Backend:** uses local `claude` CLI (no `ANTHROPIC_API_KEY` needed — uses Claude Code subscription).
- PDFs: text extracted via pdfplumber, all PDFs batched into a single Claude call for speed.
- Images: downsized to 1500px max, sent to Claude Vision one at a time via `--input-format stream-json`.

**Validation:** item sum is checked against receipt total (±€0.10). Discounts/coupons cause a `[!]` flag — not an error, just informational.

**Item categories (16 total):** `Dairy` | `Produce` | `Meat` | `Bakery` | `Beverages` | `Snacks` | `Condiments` | `Pantry` | `Household` | `Clothing` | `Pfand` | `Dining` | `Healthcare` | `Photos` | `Discounts` | `Other`

Category guidance: Condiments = mustard/pesto/sauces/oils. Pantry = sugar/flour/pasta/rice/instant soup/dry goods/spices. Clothing = all items from fashion stores (Primark etc.). Pfand = bottle deposits. Dining = restaurant/café meals. Healthcare = medicine/vitamins/supplements/protein. Photos = photo printing/services. Discounts = coupons/vouchers/negative lines. Store-level overrides: Primark → Clothing; restaurants (Saravanaa Bhavan etc.) → Dining.

**One receipt per image file** — multi-receipt images are not supported. Use CamScanner's per-document export.

## Re-categorizing transactions

When updating `scripts/parsers/categorizer.py` rules, re-apply them without re-parsing PDFs:

```python
# scratchpad/recategorize.py (already exists in temp dir, recreate if needed)
import json, sys
sys.path.insert(0, 'scripts/parsers')
from categorizer import categorize

with open('data/processed/data.json', encoding='utf-8') as f:
    data = json.load(f)

changed = 0
for stmt in data.get('bank_statements', []):
    for tx in stmt.get('transactions', []):
        old = tx.get('category', 'Other')
        new = categorize(tx.get('merchant', ''), tx.get('type', ''))
        if old != new:
            print(f"  {old:20s} -> {new:15s}  |  {tx['merchant'][:60]}")
            tx['category'] = new
            changed += 1

print(f"Changed: {changed}")
with open('data/processed/data.json', 'w', encoding='utf-8') as f:
    json.dump(data, f, ensure_ascii=False, indent=2)
```

## Categorizer rules

`scripts/parsers/categorizer.py` — ordered list of `(keywords, category)` tuples. First match wins. Categories: `Income`, `Salary`, `Rent`, `Childcare`, `Groceries`, `Dining`, `Utilities`, `Transport`, `Healthcare`, `Insurance`, `Entertainment`, `Shopping`, `Banking`, `Other`.

Rules checked early take priority — Dining comes before Insurance so `'allianz gastro'` beats `'allianz'`.

**Removed from Childcare**: `'bad vilbel'`, `'kreis'`, `'stadt bad'` — too broad, matched shop addresses in Bad Vilbel city.

## Dashboard architecture

- `dashboard/index.html` — live dashboard, no build step, no bundler; fetches JSON via HTTP
- `dashboard/standalone.html` — generated by `build.py`; data inlined as `window.__EMBEDDED_DATA__` and `window.__EMBEDDED_RECEIPTS__`; opens via `file://` without any server
- Chart.js 4.4.1 (CDN)
- `safeRender()` wraps every render function so one crash doesn't silence other tabs
- Charts in hidden tabs get 0×0 dimensions — `showPage()` calls `chart.resize()` on all canvases when a tab becomes visible
- `applyFilters()` resets `activeCatFilter = 'all'` to avoid the category pill staying active across year changes
- Receipts tab reads from `receipts.json` (live) or `window.__EMBEDDED_RECEIPTS__` (standalone); year filter scopes by `receipt.date.startsWith(year)`

## Data scope

Bank statements and payslips from **July 2022 onwards** only. Pre-July 2022 data was removed.
Receipts from **April 2026 onwards** (earliest available Kassenbon).

## What the parser does NOT handle

- SBI (State Bank of India) statements — different format, no parser written
- Other German banks (different Kontoauszug layout)
- Payslips from non-DATEV payroll systems
- Multi-receipt images — one receipt per image file required
